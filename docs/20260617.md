# 多机分布式部署方案 — 2026-06-17

## 1. 背景与目标

### 1.1 硬件资源

| 机器 | 角色 | 配置 |
|------|------|------|
| M1（入口机） | api + 基础设施 | 2T 数据盘 |
| M2 ~ M8 | Worker + 存储 | 各 2T 数据盘 |

约束：
- 对外只暴露 M1 一个公网 IP
- 每台机器同时只能执行一个任务（`concurrency=1`）
- 每台 2T 数据盘尽量利用，不做集中存储

### 1.2 目标

- 请求统一入口：外部只访问 `http://M1公网IP:80`
- 任务自动调度：空闲 Worker 自动从队列拉取任务
- 存储池化：各机器磁盘组成统一存储池，数据冗余不丢
- 上传直传：客户端上传文件直接到达存储节点（不经过 api 中转）
- Worker 就近读：Worker 处理任务时尽量从本机磁盘读取数据

## 2. 整体架构

```
公网 ──→ M1:80 (nginx)
         │
         ├── api:8000         ← FastAPI（创建/查询/SSE）
         ├── redis:6379       ← Celery 任务队列
         ├── db:5432          ← PostgreSQL
         └── minio:9000       ← MinIO 分布式（纠删码分散到各节点）
              │
         ┌────┴────┐
    M1 MinIO    M2 MinIO  ...  M8 MinIO
    /data        /data          /data
         │
    ┌────┴────┐
    Worker    Worker         Worker
    (M1 可无)   (M2)          (M8)
```

### 2.1 服务分布

| 服务 | M1 | M2 | M3 | M4 | M5 | M6 | M7 | M8 |
|------|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| nginx | ✓ | | | | | | | |
| api | ✓ | | | | | | | |
| redis | ✓ | | | | | | | |
| postgresql | ✓ | | | | | | | |
| MinIO | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Worker | | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

### 2.2 端口开放策略

| 方向 | 端口 | 协议 | 说明 | 放行范围 |
|------|------|------|------|---------|
| 公网 → M1 | 80 | HTTP | nginx 入口 | 0.0.0.0/0 |
| M1 → 各 MinIO | 9000 | HTTP | Worker 读写 MinIO | 内网子网 |
| 公网 → M1 | 9000 | HTTP | MinIO 入口（可选） | 0.0.0.0/0 |

## 3. 数据流

### 3.1 上传流程

```
浏览器 POST /tasks ──→ M1 nginx ──→ api
  │                                     │
  │   返回 uploadInfos: presigned URL    │
  │   url: http://Mi:9000/gaussian/...   │
  ▼                                     ▼
浏览器 PUT http://Mi:9000/gaussian/...
  │
  └──→ MinIO 分布式自动纠删码分散到 8 台磁盘
```

presigned URL 指向 MinIO 集群的任意节点（通过 nginx upstream 负载均衡或直连），MinIO 内部自动将数据分片存到各机器磁盘。上传完成后调用 `POST /start` 提交任务。

### 3.2 处理流程

```
POST /tasks/{id}/start ──→ api ──→ Celery chain 入 Redis 队列
                                    │
                    M2 空闲 Worker ←─┘（从 Redis 拉取）
                    │
                    读取输入文件：MINIO_ENDPOINT=M1内网IP:9000
                    │  MinIO SDK → M1:9000 → 从各节点拉分片合并
                    │
                    本地执行 4 阶段流水线
                    │
                    写入输出文件：MINIO_ENDPOINT=M1内网IP:9000
                    │  MinIO SDK → M1:9000 → 纠删码分散到各节点
                    │
                    写 DB 更新进度/状态
                    ▼
任务完成
```

### 3.3 下载流程

```
浏览器 GET /tasks/{id} ──→ api ──→ 从 DB 查文件索引
  │   返回 presigned download URL
  │   url: http://M1公网IP:9000/gaussian/...
  ▼
浏览器 GET http://M1公网IP:9000/gaussian/...
  └──→ MinIO 从各节点汇聚分片 → 返回完整文件
```

## 4. MinIO 分布式方案

### 4.1 启动方式

```bash
# 每台机器的 MinIO 容器用 host 网络模式
# 假设内网 IP 为 192.168.1.10 ~ 192.168.1.17

docker run -d --name minio \
  --restart unless-stopped \
  --network host \
  -v /data:/data \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin \
  minio/minio server \
  http://192.168.1.{10..17}:9000/data \
  --console-address ":9001"
```

一行命令启动 8 节点分布式 MinIO。

### 4.2 纠删码策略

8 节点，每节点 1 块盘，EC 配置：

| 配置 | 容错能力 | 可用容量 |
|------|---------|---------|
| 8+2 | 坏任意 2 台数据不丢 | 6/8 × 16T = 12T |
| 4+4 | 坏任意 4 台只读，4 台可写 | 4/8 × 16T = 8T |

MinIO 默认 EC: N/2（8 节点即 4+4），无需手动配置。

### 4.3 Read Locality

Worker 读文件时通过 `MINIO_ENDPOINT=M1:9000` 连接 MinIO，SDK 请求落到任意 MinIO 节点。MinIO 内部会：

1. 检查请求的纠删码分片分布
2. 优先从本机磁盘读取本地有的分片
3. 远端拉取缺失分片
4. 合并返回

Worker 和 MinIO 同机部署时（M2~M8），Worker 读取的文件有一部分分片恰好在本地磁盘，享受本地读加速。

### 4.4 MinIO Nginx 反向代理

M1 上 nginx 对 MinIO 做负载均衡（可选，直接用多节点地址也可）：

```nginx
upstream minio_cluster {
    # 使用 hash 使同一文件请求落到同一节点，提高缓存命中
    hash $request_uri consistent;
    server 192.168.1.10:9000;
    server 192.168.1.11:9000;
    server 192.168.1.12:9000;
    server 192.168.1.13:9000;
    server 192.168.1.14:9000;
    server 192.168.1.15:9000;
    server 192.168.1.16:9000;
    server 192.168.1.17:9000;
}

server {
    listen 9000;
    client_max_body_size 10G;
    location / {
        proxy_pass http://minio_cluster;
    }
}
```

## 5. 部署步骤

### 5.1 前置条件

- 所有机器 Docker 已安装
- 内网互通（各机器可互相访问）
- M1 有公网 IP 且 80/9000 端口可达
- 各机器 `/data` 目录挂载 2T 数据盘

### 5.2 M1 入口机

```yaml
# M1: docker-compose.yml
version: '3.8'
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "9000:9000"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf
    depends_on: [api, minio]

  api:
    image: registry:5000/3dgs-api:latest
    environment:
      DATABASE_URL: postgresql://postgres:password@db:5432/gaussian
      CELERY_BROKER_URL: redis://redis:6379/0
      MINIO_ENDPOINT: 127.0.0.1:9000
      MINIO_PUBLIC_ENDPOINT: M1公网IP:9000
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
      USE_LOCAL_STORAGE: "false"
      SERVICE_ACCOUNTS: dev-admin:sk-debug
      JWT_SECRET_KEY: ...

  redis:
    image: redis:7-alpine

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_PASSWORD: password
    volumes:
      - /data/pgdata:/var/lib/postgresql/data

  minio:
    image: minio/minio
    network_mode: host
    command: server http://192.168.1.{10..17}:9000/data --console-address ":9001"
    volumes:
      - /data/minio:/data
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
```

### 5.3 M2 ~ M8 Worker 节点

每台机器上运行：

```yaml
# Mi: docker-compose.yml
version: '3.8'
services:
  minio:
    image: minio/minio
    network_mode: host
    command: server http://192.168.1.{10..17}:9000/data --console-address ":9001"
    volumes:
      - /data:/data
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin

  worker:
    image: registry:5000/3dgs-worker:latest
    network_mode: host
    environment:
      DATABASE_URL: postgresql://postgres:password@M1内网IP:5432/gaussian
      CELERY_BROKER_URL: redis://M1内网IP:6379/0
      MINIO_ENDPOINT: 127.0.0.1:9000
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
      USE_LOCAL_STORAGE: "false"
      ALG_ENABLED: "false"
      SERVICE_ACCOUNTS: dev-admin:sk-debug
      JWT_SECRET_KEY: ...
```

关键点：
- `MINIO_ENDPOINT=127.0.0.1:9000` — Worker 通过本机 MinIO 进程读写，享受 read locality
- `network_mode: host` — 避免容器内 localhost 冲突，MinIO 分布式要求节点间直连
- worker 不需要开任何端口

### 5.4 构建镜像并分发

```bash
# 在 CI 或任意一台机器构建
docker build -t registry:5000/3dgs-api:latest -f Dockerfile.api .
docker build -t registry:5000/3dgs-worker:latest -f Dockerfile.worker .
docker push registry:5000/3dgs-api:latest
docker push registry:5000/3dgs-worker:latest

# 各机器 pull
docker pull registry:5000/3dgs-api:latest
docker pull registry:5000/3dgs-worker:latest
```

无 registry 时可用 `docker save` + `scp` + `docker load` 分发。

## 6. 现有代码改动

### 6.1 需要改动的文件

**`backend/core/config.py`** — `MINIO_ENDPOINT` 支持从环境变量读取（已支持，无需改）

**`backend/core/minio_storage.py`** — 确认 `get_presigned_put_url` 生成的 URL 使用 `MINIO_PUBLIC_ENDPOINT` 替代 `MINIO_ENDPOINT` 作为域名

**检查 `backend/core/minio_storage.py` 第 75-80 行的预签名 URL 生成逻辑**：

```python
# 当前预期逻辑（需确认实现）
public_endpoint = settings.minio_public_endpoint or settings.minio_endpoint
# presigned URL 的 host 应为 public_endpoint
# 这样才能保证浏览器能访问到 M1:9000（经过 nginx 反向代理）
```

### 6.2 无需改动的部分

| 模块 | 原因 |
|------|------|
| API 路由 | 全部通过环境变量配置连接地址，不涉及多机逻辑 |
| Worker 任务 | Celery 从 Redis 拉任务，完全不感知机器分布 |
| TaskRepository | DB 操作由 SQLAlchemy 处理连接池，多机无影响 |
| Redis 队列 | Celery 原生支持分布式 Worker |
| 前端 | 只请求 `M1公网IP:80`，不感知后端架构 |

### 6.3 确认清单

- [ ] `MINIO_PUBLIC_ENDPOINT` 配置后，预签名 URL 正确使用该地址
- [ ] 关闭 `USE_LOCAL_STORAGE`（分布式场景不能走本地文件系统）
- [ ] Worker 不挂载 docker.sock（外部算法模式需额外处理）
- [ ] PostgreSQL 配置 `listen_addresses=*` 允许内网 Worker 连接
- [ ] Redis 绑定内网 IP（`bind 0.0.0.0` 或指定内网网卡）
- [ ] 各机器时区一致（UTC）
- [ ] `.env` 中的密钥、密码等不要写死在 docker-compose.yml

## 8. 关键决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 存储方案 | MinIO 分布式（非每机独立存储） | 统一命名空间，数据冗余，简化 Worker 逻辑 |
| Worker 存储地址 | `MINIO_ENDPOINT=127.0.0.1:9000` | 本机 MinIO 进程就近读，减少跨机网络 IO |
| 入口暴露 | nginx 反代 api + MinIO | 统一端口 80/9000，内部拓扑对外透明 |
| 预签名 URL | 指向 `MINIO_PUBLIC_ENDPOINT` | 浏览器直传 MinIO，不经过 api 中转 |
| MinIO 网络 | `host` 模式 | 分布式要求节点间直接通信，bridge 模式需额外端口映射 |
| EC 级别 | MinIO 默认 N/2 | 兼顾容量利用率和容错性（8 节点可坏 4 台） |
